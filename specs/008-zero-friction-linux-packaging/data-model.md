# Data Model: Zero-Friction Linux Packaging

## Entities

### 1. Release Artifact

Represents a single build artifact published to GitHub Releases.

| Field | Type | Description | Constraints |
|-------|------|-------------|-------------|
| `id` | string | Unique identifier (e.g., `lnta_0.8.0_linux_amd64.deb`) | Format: `{name}_{version}_{os}_{arch}.{ext}` |
| `name` | string | Project name | Constant: `lnta` |
| `version` | string | Semantic version (e.g., `0.8.0`) | Per Constitution: MAJOR.MINOR.PATCH |
| `os` | string | Target operating system | Constant: `linux` |
| `arch` | string | Target architecture | Enum: `amd64`, `arm64` |
| `format` | string | Package/binary format | Enum: `deb`, `rpm`, `pkg.tar.zst`, `tar.gz` |
| `sha256` | string | SHA-256 checksum (64 hex chars) | Generated by GoReleaser |
| `size_bytes` | int | File size in bytes | < 15,000,000 (15MB) |
| `download_url` | string | GitHub Release asset URL | `https://github.com/sm-me/lnta/releases/download/v{version}/{id}` |

**Relationships**:
- One Release → Many Release Artifacts (2 arches × 4 formats = 8 primary artifacts + checksums.txt)

### 2. Package Metadata (nfpm)

Configuration for each Linux package format.

| Field | Type | Description | Constraints |
|-------|------|-------------|-------------|
| `id` | string | GoReleaser nfpm identifier | Enum: `deb`, `rpm`, `archlinux` |
| `format` | string | Package format | Enum: `deb`, `rpm`, `archlinux` |
| `package_name` | string | Name in package manager | Constant: `lnta` |
| `bindir` | string | Installation directory for binary | Constant: `/usr/bin` |
| `maintainer` | string | Package maintainer | `"LNTA Maintainers <maintainers@lnta.dev>"` |
| `description` | string | Short description | `"Linux Natural-Language Terminal Assistant"` |
| `license` | string | SPDX license identifier | `"MIT"` |
| `recommends` | string[] | Recommended dependencies | `["bubblewrap", "desktop-file-validate"]` |
| `scripts` | object | Lifecycle scripts | See Scripts entity |
| `contents` | array | Additional files to package | See Contents entity |

---

### 3. Package Scripts (Debian-specific)

Lifecycle scripts for `.deb` package (AppArmor integration).

| Script | Trigger | Content | Purpose |
|--------|---------|---------|---------|
| `postinstall` | After package unpack | `apparmor_parser -r /etc/apparmor.d/lnta \|\| true` | Load AppArmor profile for bwrap |
| `preremove` | Before package removal | `apparmor_parser -R /etc/apparmor.d/lnta \|\| true` | Unload AppArmor profile |
| `postremove` | After package removal | `rm -f /etc/apparmor.d/lnta` | Clean up profile file |

**Note**: Only `.deb` format includes these scripts. `.rpm` and `.pkg.tar.zst` rely on systemd/AppArmor integration via distro mechanisms.

---

### 4. Package Contents (Debian-specific)

Additional files bundled in `.deb`.

| Field | Type | Description |
|-------|------|-------------|
| `src` | string | Source path in repo | `scripts/apparmor-profile` |
| `dst` | string | Destination path in package | `/etc/apparmor.d/lnta` |
| `type` | string | File type | `config` (preserves on upgrade) |
| `packager` | string | Target packager | `deb` (only for Debian) |

### 6. Install Script Context

Runtime data for `scripts/install.sh` execution.

| Field | Type | Description | Source |
|-------|------|-------------|--------|
| `arch` | string | Detected architecture | `uname -m` mapping |
| `distro_id` | string | OS identifier | `/etc/os-release` ID |
| `distro_like` | string | OS family | `/etc/os-release` ID_LIKE |
| `pkg_format` | string | Selected package format | Derived from distro |
| `version` | string | Latest release version | GitHub API |
| `asset_name` | string | Asset filename | Derived from version/arch/format |
| `checksum` | string | Expected SHA-256 | `checksums.txt` from release |

### 7. Man Page Structure

Generated by `cobra/doc.GenManTree` from Cobra command tree.

| Section | Source | Content |
|---------|--------|---------|
| NAME | `rootCmd.Use` + `rootCmd.Short` | `lnta - LNTA — Linux Natural-Language Terminal Assistant` |
| SYNOPSIS | `rootCmd.Use` + flags + args | `lnta [flags] [prompt]...` |
| DESCRIPTION | `rootCmd.Long` | Full description from root command |
| OPTIONS | Persistent flags + command flags | Auto-generated from Cobra |
| COMMANDS | Subcommands (`chat`, `undo`, `packs`, `doctor`, `init`, `fix`, `mcp`, `docs`, `completion`) | Auto-generated |
| EXAMPLES | Custom (added in `docs_cmd.go`) | Common usage patterns |
| FILES | Config paths | `~/.config/lnta/`, `~/.local/share/lnta/snapshots/` |
| SEE ALSO | Related commands | Shell integration, GitHub repo |

### 8. Shell Completion Spec

Generated by Cobra's built-in generators.

| Shell | Generator Function | Output Target | Activation |
|-------|-------------------|---------------|------------|
| bash | `rootCmd.GenBashCompletion(w)` | stdout → `source <(lnta completion bash)` | `~/.bash_completion` or `/etc/bash_completion.d/` |
| zsh | `rootCmd.GenZshCompletion(w)` | stdout → `source <(lnta completion zsh)` | `~/.zshrc` or `$fpath` |
| fish | `rootCmd.GenFishCompletion(w, true)` | stdout → `lnta completion fish \| source` | `~/.config/fish/completions/` |

### 9. VHS Scene

Represents one scene in the demo recording.

| Field | Type | Description |
|-------|------|-------------|
| `scene` | int | Scene number (1-3) |
| `command` | string | Command typed |
| `expected_output` | string | Key output to verify |
| `duration_sec` | int | Approximate scene duration |

**Scenes**:
1. `lnta "create a desktop launcher..."` → Fingerprint + bwrap check + diff + validation receipt (3s)
2. `lnta undo` → Reverts change in ~1s (2s)
3. `journalctl -n 20 | lnta "explain what's failing"` → Pipe ingestion + LLM analysis (3s)

### 10. CI/CD Pipeline Configuration

| Pipeline | File | Trigger | Jobs |
|----------|------|---------|------|
| CI | `.github/workflows/ci.yml` | PR push, main branch | `vet`, `lint`, `packs-validate`, `test-race` |
| Release | `.github/workflows/release.yml` | Git tag `v*` | `goreleaser` |

**CI Job Details**:
- `vet`: `go vet ./...`
- `lint`: `golangci-lint run` (with bubblewrap installed)
- `packs-validate`: `lnta packs validate --strict`
- `test-race`: `go test -race -v ./...` (requires bubblewrap for sandbox tests)

## Validation Rules

1. **Release Artifact**: Every artifact must have matching entry in `checksums.txt`
2. **Package Metadata**: All nfpm configs must declare `recommends: ["bubblewrap", "desktop-file-validate"]`
3. **AppArmor Scripts**: `.deb` must have all 3 lifecycle scripts with `|| true` for graceful failure
4. **Install Script**: Must support all 4 package formats + binary fallback
5. **Man Page**: Must include all CLI commands and flags
6. **Completions**: Must support all 3 shells with subcommand/flag completion
7. **VHS Tape**: Must produce valid GIF with 3 scenes
8. **CI**: All 4 jobs must pass on PR
9. **Release**: Must publish 10+ artifacts on tag push
